# 剩余素材清单 · 2026-11-16（R3 收尾）

本页只列**真正缺的件**和**缺件期间的替代做法**。目的：不让开发停在笼统的「待美术」。
每一项都写明：缺什么、规格、缺它时现在能做什么、什么时候必须等它。

---

## 一、下一阶段最高优先级

### 1. 主角连续步态（6–8 帧）

**现状**：五张立绘是静态姿态（正面/侧面/背面/行走/对山歌），`hero-walk.webp` 只是
一张跨步定格。现在「行走」是平移这一张图并叠加轻微上下浮动，**不是**步态动画。

| 项 | 要求 |
| --- | --- |
| 帧数 | 6–8 帧一个完整迈步循环（左右脚各一次着地） |
| 规格 | 透明 PNG/WebP，同一画布尺寸、同一人物高度、脚底基线对齐 |
| 命名 | `hero-walk-01.webp` … `hero-walk-0N.webp` |
| 现状替代 | 单帧 + 位移；不声称是步态动画 |
| 必须等它才能做 | 真步态、行走节奏与地面接触的细节打磨 |

**为什么必须整帧**：把单张立绘做骨骼变形或模糊插帧会破坏手绘线条，
不符合「保留原幅画质」的既有约定。

### 2. 鸬鹚捕鱼动作

**现状**：`npc-cormorant.webp` 是一张静态插画，点击有对白，没有潜水/出水动作。

| 项 | 要求 |
| --- | --- |
| 帧数 | 潜水入水 3 帧 + 出水衔鱼 3 帧（可分两段交付） |
| 规格 | 透明，与现有 `npc-cormorant.webp` 同画布、同锚点 |

### 3. 渔人收鱼动作

**现状**：鱼市是**纯文字状态机**（等待→挑选→确认→完成），结果只存在于文案里，
画面上没有道具交接。

| 项 | 要求 |
| --- | --- |
| 帧数 | 递鱼 3–4 帧（摊主伸手 → 交接 → 收回） |
| 需要 | 主角与摊主**同一画面**的手部对齐，或分成两张可叠加的图 |
| 缺件时可做 | 已做：鱼市结果记忆、取消、重复点击保护都在；可直接接一段文字+插画淡入 |
| 必须等它才能做 | 「结果连接到可见道具交接」 |

## 二、第二阶段

| 素材 | 用途 | 规格 | 缺件时现状 |
| --- | --- | --- | --- |
| 正式山歌人声 + 字幕 | 夜游「对山歌」 | 授权人声，配逐句字幕文件 | 只有姿态演示，界面已注明不是演唱 |
| 船体前后分层 | 船上视角行走 | 前层/船身/后层三张对齐图 | 游船是单张插画，只能整体漂移 |
| 桥栏矢量遮罩 | 替换阈值抠图 | SVG 或手工分层 PNG | 现用阈值+连通域，近看柱边有锯齿 |
| 无人机飞行轨迹 | 若要做「编队」而非画稿 | 轨迹数据 + 分帧光点 | 现为二维画稿欣赏，界面已注明非实时编队 |

## 三、缺件期间已经能做、且不依赖美术的部分

这些**不需要等素材**，可以继续推进：

- 桥栏抠图改矢量遮罩（纯代码 + 现有原画）
- 逐步补齐夕照/夜景其余前景层（塔、亭）的遮挡
- 鱼市文案与结果的进一步细化（已有状态机，改文案即可）
- 无障碍与键盘操作路径补全
- 真机测试（需要设备，不是素材）

---

## 四、素材交付时必须同时登记

按 `docs/ASSETS.md` 的既有要求，新素材入库需登记：尺寸、作者、授权范围、
是否分层、以及是否与 `verify-assets.mjs` 的预算一致。缺这些登记的文件不接。
