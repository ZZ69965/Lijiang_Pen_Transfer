# 取景、站位与局部动效（2026-11-13 R2）

本轮修掉的核心问题：**人物像漂在水面上**。原因不是精灵锚点或缩放，而是数据与职责混在一起：

1. `WALKWAY` 是一条凭目测填的等高线，整卷几乎恒在 y≈460——那正好是**江面**的高度。
2. `focusPlace()` 把「镜头要对准哪里」和「人物要站到哪里」当成同一个值 `place.worldX`。
   可是象鼻山在画里是**江心孤岛**，周围全是水；把人物送到 `worldX=172`，就是送进河里。

## 现在分成三件事

| 概念 | 数据 | 用途 |
| --- | --- | --- |
| 取景点 | `Place.worldX` | 镜头中心。指画中的主体（桥拱、双塔），**不是**站立处 |
| 站点 | `Place.standX` | 人物实际站立处，必须落在 `WALKABLE_SPANS` 内 |
| 地面线 | `WALKWAY`（`walkwayY()`） | 站立处的地面高度，逐点贴着画出来的石岸/桥面 |

象鼻山因此拆成两个数：镜头对 `172`（把桥拱和倒影放进画面），人物站 `620`
（对岸石阶上，隔着水面看它）。`clampHeroX()` 会把任何输入吸附到最近的**陆地**，
所以无论行走、跳点、还是快照恢复，都不可能再把人放到水上。

### 地面是量出来的，不是估的

对着 `scene-day.webp` 的 2× 网格裁切逐段读石岸上沿：

- 左岸石驳岸上沿 y≈503–508（栏杆顶在 y≈478，脚要踩在石面上而不是水里）
- 阳桥桥面 y≈400
- 右岸/鱼市平台 y≈508
- 象鼻山孤岛、玻璃桥跨度：**不可行走**

`review` 字段保留诚实标注：桥段仍是 `pending`（见下）。

## 人物尺度

`HERO_HEIGHT` 从 116 降到 96。标定参照是画中石驳岸护墙（约 34 世界像素 ≈ 腰高），
站立人身高应约为它的 2.8 倍。五张姿态仍然共用一个 `HERO_SCALE`——这是刻意的，
按姿态分别对齐高度会让行走帧突然“长高”。

## 取景缩放

每个景有 `Place.zoom`（相对适配缩放的系数）：象鼻山 1.16 让桥拱有呼吸空间，
双塔 1.0 保证双塔与石桥同框。引擎会把它夹在
`max(用户最小缩放, 填满视口所需缩放)` 与 `最大缩放` 之间——**低于填满视口会出现米色边条**，
这条下限是必须的，已写进 `focusPlace()`。

## 局部动效

每个景只有一处克制的动效：主体前水面上的三道缓慢流光（独立 `Graphics` 层，
`ambientLayer`，**不改原画任何像素**）。`prefers-reduced-motion` 下整段跳过，
因此静态截图与静止状态完全一致——先让静态画面站住，再谈动效。
